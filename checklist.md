# Project review checklist

What reviewers in this repo most often miss, grouped by area. This complements — it does not replace — `CLAUDE.md` and `standards/*.md`; when a rule there and here disagree, the standards file wins (and the disagreement is itself worth flagging so this file gets fixed).

Only raise an item when the MR actually touches the relevant area.

## Everywhere

- **Intent match** — does the code do what the MR description / Jira ticket says? Missing edge cases the ticket implies?
- **Branch and commit naming** — branch and every commit message start with `CF-\d{2,5}`.
- **Docs in the same change** — behavior change with no matching update to READMEs, docstrings, `docs/*.md`, `CLAUDE.md`, or standards. Walk producer → consumer: if a payload shape changed, are both ends and their docs updated?
- **TODOs** — every new `TODO` carries a ticket: `TODO(CF-123): ...`.
- **Suppressed checks** — any new `# noqa`, `# type: ignore`, `# fmt: off`, `eslint-disable`, `@ts-ignore`, `@ts-expect-error`, or loosened lint/CI config is blocking unless the MR explains why the developer was told it's acceptable.
- **Secrets** — no credentials, DB URLs, tokens, or account-specific secrets in code, tests, docs, or fixtures (even fake-looking ones).
- **Reuse over rewrite** — new helper that duplicates something in `shared/`, `db/`, an existing construct in `cdk/lib/constructs/`, or a frontend composable. Search before accepting a new utility.

## Python (api/, lambdas/, db/, db_migrations/, shared/)

- Full type hints and explicit return types (including `-> None`).
- Absolute imports only — no `from .` / `from ..` (breaks the `__main__` handler run).
- No function-level imports.
- Module names prefixed with the package short name (`status_reader_queries.py`), schema files singular.
- Pydantic v2 at edges with `extra="forbid"` on small schemas; API models inherit `APIModel` imported from `api.api_schema` (not `api_app`, which is circular).
- **Destructive SQL/ORM** (`DELETE`, `DROP`, `TRUNCATE`, `.delete()`, `drop_all()`) — the standard says these must be hand-written by an engineer. In a review, don't reject them outright; check the intent is deliberate, scoped (a `WHERE` that can't match everything), transactional, and called out in the MR description.
- Queries: plain functions taking a `Session`, `select(...)` + `session.scalar(s)`; no repository classes. Watch for N+1 loops, missing `.where`, unbounded result sets, and missing commits/rollbacks.
- Vendor (Dayzer) tables use a separate `VendorBase`, never the app `Base` (otherwise Alembic will try to manage them).
- Alembic: migration generated by `just alembic-create` (autogenerated header, real revision chain — check `down_revision` matches the current head on `main`), reviewed for autogenerate misses (server defaults, enums, index names), and has a working `downgrade`.
- Lambda handlers: `configure_logging()` is the first statement; cold-start work in a memoized init, not module scope; file ends with an `if __name__ == "__main__":` block; no `logging.basicConfig`.
- Error handling: exceptions at system boundaries (DB, S3, SSM, Step Functions, Dayzer host) are caught with context and logged structurally; HTTP errors return generic messages, detail goes to logs.
- Tests: pytest + fixtures + `monkeypatch`; boto3 tested with `botocore.stub.Stubber` and injected clients — flag `unittest.mock`, `MagicMock`, `patch`, `TestCase`, `moto`, or hand-written stub classes. New business logic has unit tests; new DB queries/endpoints have integration tests.
- New runtime dependency added to the right member's `pyproject.toml` (not the root), `uv.lock` updated, `boto3` not added as a runtime dep.

## CDK (cdk/)

- Stateful resources (S3 with data, DB, secrets, KMS, hosted zones) go in `PersistentStack` with `RemovalPolicy.RETAIN`. Anything stateful added to `AppStack` is blocking — moving it later is painful.
- Cross-stack references via `props.persistent`, not ARN strings.
- Every Lambda has an explicit `logs.LogGroup` with `RetentionDays.TWO_MONTHS`, wired via `logGroup`, `RemovalPolicy.DESTROY` in the app stack.
- IAM: least privilege — no `*` actions/resources without justification; grants via `bucket.grantRead(fn)`-style helpers where available.
- Renamed construct IDs on existing resources cause replacement (data loss for stateful resources) — check logical IDs didn't change unintentionally.
- Per-stage config passed as typed props from `cdk/bin/cdk.ts`; nothing hardcoded per account.
- Snapshot/assertion tests updated alongside the change.

## Frontend (frontend/)

- Vue 3 Composition API, strict TypeScript — no `any` escape hatches.
- Existing composables/components reused; PrimeVue unstyled mode respected.
- API calls handle loading, empty, and error states; auth token handling unchanged unless intended.
- Vitest coverage for new logic-bearing composables/utilities.

## Domain sanity (Dayzer / SPP auction work)

- Units and sign conventions for prices, basis (DA vs RT), and MW are consistent with existing code; new calculations state them.
- Hour-ending vs hour-beginning, timezone (market time vs UTC), and DST handling on any time-series join.
- Dev has no Dayzer license — new pipeline steps must keep a working mock/fake path in dev.
